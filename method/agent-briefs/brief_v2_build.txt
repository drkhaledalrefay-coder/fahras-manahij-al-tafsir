   Deterministic marker detection per span (normalized match, keep original offsets). Marker families (extend sensibly, document each regex in method/markers_v2.md):

   - LUGHA: «أي:» «معناه» «يقال» «والعرب تقول» «في اللغة» «قال الشاعر» «وأنشد» «كقول».
   - QIRAAT: «قرأ» «قراءة» «وفي قراءة» «قرأه».
   - NUZUL: «نزلت في» «سبب نزول» «فأنزل الله» «فنزلت».

3. src/v2_packets.py -> data/v2/packets/<id>.json and method/classifier_prompt_v2.md
   A self-contained input packet for ONE classifier model per window: definitions (from design_v2.md section 1, in Arabic), certainty-level rules, the span list, per-span marker hits, editor-footnote evidence (clearly labeled "حاشية المحقق — ليست من كلام ابن كثير"), and the exact output JSON schema below. The prompt must say: return span IDs only, never text; refuse (certainty "insufficient") when evidence is missing; one primary method per move (or null for pure takhrij), optional secondary methods.
   OUTPUT SCHEMA the classifier must return:
   { "window": "...", "moves": [ { "move_id": "m01", "span_ids": [...], "primary": "M_QURAN|M_SUNNAH|M_SAHABA|M_TABIIN|M_LUGHA|M_QIRAAT|M_NUZUL|M_SIRA|M_ISRAILIYYAT|M_RAY|null", "secondary": [], "content_tags": [], "certainty": "explicit|strong|weak|insufficient", "evidence_span_ids": [...], "author_verdict_span_ids": [...], "references": {"verses": [], "hadith": [], "persons": []}, "alternatives": [], "rationale_ar": "≤25 words, no quotes >4 words" } ] }

4. src/v2_verify.py -> data/v2/verified/<annotator>/<id>.json
   Reads data/v2/moves/<annotator>/<id>.json (to be produced LATER by a classifier run — NOT by you), and:
   - validates IDs, contiguity, non-overlap; rebuilds text from the pinned source and asserts verbatim;
   - rule checks from design_v2.md (e.g. M_QURAN needs a QURAN marker in evidence spans and is flagged if the only verse sits inside a hadith quotation; M_SAHABA/M_TABIIN flagged if the name appears only inside an ISNAD range; M_ISRAILIYYAT needs an ISRAILIYYAT marker or author verdict; M_NUZUL needs a NUZUL marker; editor footnotes support attribution/grading only);
   - computes the auditable score per design_v2.md: marker 25 + function evidence 45 + attribution 15 + boundary completeness 15; cap 59 if no function evidence; downgrade certainty when a rule fails;
   - assigns route: auto_candidate (explicit/strong, score ≥ 75, no rule flag) or specialist (everything else, plus all M_ISRAILIYYAT, M_NUZUL, M_QIRAAT, Sahabi/Tabi'i ambiguity, mixed spans);
   - writes a per-window summary and reports/v2_summary.md.
