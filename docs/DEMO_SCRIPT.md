# سكربت العرض الحي — الذكاء وهو يعمل

خطوات موجودة فقط في المستودع. لا توقيت موعود للحكام.

## قبل العرض

- [ ] `LLM_API_KEY` و`LLM_BASE_URL` و`LLM_MODEL` معيّنة في جلسة الطرفية فقط (لا ملف، لا مستودع)
- [ ] `--dry-run` نجح وطبع `dry-run: no network call`
- [ ] `prompt.txt` جاهز كبديل (`--manual-out`) إن فشل المفتاح أو الشبكة
- [ ] للمسار أ: `python src/demo_server.py` على المنفذ 8791 (المفتاح في بيئة العملية فقط، لا في الصفحة)

## المسار أ — من داخل الموقع (`python src/demo_server.py`)

المفتاح يبقى في بيئة عملية الخادم المحلية؛ الصفحة تستدعي `/api/run` على `127.0.0.1` فقط. الاستضافة الثابتة (`python -m http.server`) لا تُظهر الزر.

### 1. تعيين البيئة (جلسة الطرفية فقط)

من جذر المستودع:

```bash
# PowerShell
$env:LLM_API_KEY = "..."
$env:LLM_BASE_URL = "https://api.openai.com/v1"
$env:LLM_MODEL = "gpt-4o-mini"
```

لا تتركوا قيمة المفتاح ظاهرة على الشاشة. التفصيل: [`AI_RUN.md`](AI_RUN.md).

### 2. تشغيل الخادم المحلي

```bash
python src/demo_server.py
```

افتحوا http://127.0.0.1:8791/fahras.html — اختاروا الطبري والآية 2:102. يظهر زر «شغّل الذكاء على هذه الآية» بجانب الآية فقط لأن `/api/health` استجاب.

### 3. التشغيل من الصفحة

اضغطوا الزر → «جارٍ التشغيل…» → بطاقة بالعدادات (اقتراحات / مرشّح للقبول / بانتظار المتخصص / أعلام / مرفوض) ثم «أعد تحميل الصفحة لعرض النتائج» لاختيار النموذج الجديد في قائمة «النموذج».

مهلة الطلب في الكود ١٢٠ ثانية. لا تَعِدوا الحكام برقم زمني.

### 4. قراءة اللوحة بعد إعادة التحميل

- بلا ✓ = «مقترح آلي»؛ مع ✓ = «معتمد».
- كل تمييز قادم من النموذج يبدأ `AI_PROPOSED`.
- الشريحتان: «مرشح للقبول» و«بانتظار المتخصص».

### 5. فشل المفتاح أو الشبكة — البديل

إن ظهرت رسالة تشير إلى `AI_RUN.md` أو «use manual paste fallback»، انتقلوا إلى المسار ب (اليدوي) أدناه.

للبروفة بلا مفتاح/شبكة (اختبارات ولقطات فقط): `python src/demo_server.py --fake` — البطاقة تقول «وضع تجريبي — لا يستدعي نموذجاً».

## المسار ب — من الطرفية (`run_window.py`)

### 1. تعيين البيئة (جلسة الطرفية فقط)

نفس متغيّرات المسار أ. التفصيل: [`AI_RUN.md`](AI_RUN.md).

### 2. تجربة بلا شبكة

```bash
python src/run_window.py --tafsir al_tabari --window 2_102 --dry-run
```

يطبع الحزمة وبداية التعليمات ثم `dry-run: no network call`.

### 3. استدعاء حي

```bash
python src/run_window.py --tafsir al_tabari --window 2_102 --api
```

يظهر `wrote moves: …` ثم `verifier: moves=… auto=… specialist=… flags=…`.

### 4. إعادة بناء الصفحة وفتحها

```bash
python src/build_fahras.py
python -m http.server 8791 --directory web
```

افتحوا http://127.0.0.1:8791/fahras.html — اختاروا الطبري، والآية 2:102، والنموذج الجديد من قائمة «النموذج». (مع الاستضافة الثابتة لا يظهر زر التشغيل من الصفحة.)

### 5. قراءة اللوحة

- بلا ✓ = «مقترح آلي»؛ مع ✓ = «معتمد».
- كل تمييز قادم من النموذج يبدأ `AI_PROPOSED`.
- الشريحتان: «مرشح للقبول» و«بانتظار المتخصص».

### 6. مراجعة موضع واحد (بروفة متصفح)

اضغطوا موضعاً: الدرج يعرض «أعلام:» إن وُجدت. «ابدأ المراجعة» ثم «قارن بالمصدر» ثم «اعتماد» فيظهر ✓ في هذا المتصفح فقط (`localStorage`).

**ملاحظة صدق:** علامة ✓ بروفة مراجعة داخل المتصفح، وليست اعتماداً في البيانات.

### 7. خرج سيئ (إن سُئلتم)

- ملف JSON بمعرّف span غير موجود ثم `--manual-in` يتوقف عند `invalid span ids` ولا يكتب ملفاً.
- معرّفات صحيحة ومنهج غلط: المدقق يُبقي الحركة، يضع علماً، ويوجّهها `specialist`، ولا يعطي `auto_candidate` ما دام هناك علم.

### 8. فشل المفتاح أو الشبكة — البديل الجاهز

قد يظهر `LLM_API_KEY is not set` أو `network error` أو `HTTP …`؛ والكتابة لا تحدث إلا بعد النجاح.

```bash
python src/run_window.py --tafsir al_tabari --window 2_102 --manual-out prompt.txt
# الصقوا في أي محادثة، احفظوا الرد، ثم:
python src/run_window.py --tafsir al_tabari --window 2_102 --manual-in reply.json
```

ثم كرّروا الخطوة 4.

## حدود لا تُخفى

- المفتاح **ممنوع** في `web/` وفي git؛ المسار أ يبقيه في بيئة `demo_server` على `127.0.0.1` فقط.
- الاستضافة الثابتة لا تستدعي نموذجاً ولا تُظهر الزر.
- لا توقيت موعود لنجاح الاستدعاء الحي.
- ✓ في الواجهة = بروفة مراجعة متصفح، لا اعتماد بيانات.
