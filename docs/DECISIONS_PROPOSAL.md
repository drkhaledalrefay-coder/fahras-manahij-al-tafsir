# مقترح: مصدر حقيقة لقرارات الاعتماد

هدف هذا المستند: جعل قرار المتخصص **ملتقَىً مكتوباً في المستودع** بدل `localStorage` وحده، بلا تغيير مخطط `schema/annotation.schema.json`.

## المصدر المقترح

المسار: `data/<base>/reviews/<reviewer>/<window>.json`

- `<base>`: نفس أساس التصنيف (`data/v2`، `data/multi/al_tabari`، …).
- `<reviewer>`: معرّف بشري ثابت يمرّره المشغّل (مثال: `specialist_a`) — ليس حالة اعتماد يكتبها الوكيل.
- `<window>`: مفتاح النافذة (`2_255`، `2_255_tafsir`، …).
- المحتوى: مصفوفة سجلات (أو كائن فيه `annotations`) تطابق ما تصدّره الواجهة («تصدير كل المعتمد» / «تصدير هذا الموضع»)، ويُقبل فقط ما يمرّ على:
  1. `schema/annotation.schema.json` عبر منطق `src/export_approved.py`
  2. مطابقة حرفية للنص المثبّت (`fidelity_errors`)

الملفات **تُلتزَم في git** بعد مراجعة بشرية. لا يكتب أي وكيل حالة `approved` من عنده.

## تذكير الواجهة (قبل المغادرة)

في شاشة المراجعة: تنبيه ثابت عند «تصدير ▾» + تحذير `beforeunload` إن وُجدت تمييزات معتمدة في الجلسة ولم يُنسَخ التصدير بعد. النص المقترح: «صدّر المعتمد قبل إغلاق الصفحة — الاعتماد في المتصفح فقط حتى الاستيراد». **تنفيذ الواجهة مؤجَّل** إن تعارض مع فرع رابط «جرّب الواجهة الجديدة»؛ لا حاجة لتغيير المخطط.

## تشغيل بشري (اليوم، بلا تغيير مخطط)

1. في الصفحة: اعتمد بعد «قارن بالمصدر» ثم «تصدير كل المعتمد (JSON)» وانسخ الملف.
2. من جذر المستودع:

```bash
python src/import_reviews.py export.json --base data/v2 --reviewer specialist_a --out-root <explicit-root>
```

`--out-root` **مطلوب** (لا افتراضي). الكتابة تحت `data/` في المستودع تحدث فقط إذا مرّر المشغّل جذراً يؤول إلى ذلك صراحةً (مثال: جذر المستودع عند الاستيراد الحقيقي). للاختبار استخدم مجلداً مؤقتاً؛ **لا تُكتب مراجعات وهمية تحت `data/` في الفرع**.

3. راجع `git diff` تحت `reviews/` ثم التزم يدوياً.

## حدود هذا الجزء

لا تغيير على المخطط. لا Write API ولا مصادقة. المرحلة التالية (خارج النطاق): ربط التصدير مباشرة بالمسار أعلاه بعد موافقة الفريق.
