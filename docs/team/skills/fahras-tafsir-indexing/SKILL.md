# وسم مناهج التفسير — مشغّل الذكاء (Ollama)

> المصادر الملزمة لهذه المهارة: `docs/TAGGING_PLAN_NUR.md`، `docs/COMMITTEE_PLAN.md`،
> `src/v2_packets.py`، `src/v2_verify.py`، `src/grounding_contract.py`،
> `src/run_window.py`، `src/run_surah.py`، `src/classify_api.py`، `AGENTS.md`، `docs/HANDOFF.md`.
> أي رقم أو أمر أو رمز هنا مأخوذ منها حرفياً — لا تخترع غيرها.
> التفاصيل في `references/`: الجداول الكاملة للمناهج (`methods.md`) ورموز الأسباب (`reason-codes.md`) وخطوات التشغيل (`runbook.md`).

## 1. ما المنتج (وما الذي ليس منتجاً)

- المنتج **فهرس**: يؤرشف **المنهج** الذي استخدمه المفسّر داخل نص مصدري مثبّت لا يتغيّر (`docs/TAGGING_PLAN_NUR.md` §1، `AGENTS.md`).
- النموذج يقترح حدود المقاطع والوسوم **بمعرّفات المقاطع (span IDs) فقط** — لا يعيد كتابة النص أبداً.
- الأداة **تفهرس ولا تفسّر**: ممنوع إنتاج شرح آية أو جواب ديني (`AGENTS.md` القاعدة 2).
- الحالة: نموذج بحثي تجريبي، **ولا وحدة معتمدة من متخصص بعد** (`AGENTS.md`).

## 2. خط الأنابيب (Pipeline)

1. **نافذة (window)** من النص المثبّت ← **حزمة (packet)** بأجزاء مرقّمة (`s001`…).
2. **وكيلان من عائلتين مختلفتين**: مصنّف (عائلة Qwen) + مدقّق إعادة تصنيف (عائلة مختلفة، مثل Gemma) — نفس الحزمة ونفس الفاحص (`docs/TAGGING_PLAN_NUR.md` §3، `docs/COMMITTEE_PLAN.md` §و-2).
3. **فاحص حتمي** (`python src/v2_verify.py --base <base>`) يتحقق من المصدر والحدود وكفاية الشاهد.
4. النتيجة لكل حركة: **«مرشّح للمراجعة» (`auto_candidate`)** أو **«امتناع» (`specialist`) مع رمز سبب واحد** من القائمة المغلقة (`src/grounding_contract.py`).
5. **الاعتماد للمتخصص البشري فقط** عبر واجهة المراجعة — لا اعتماد آلي أبداً.

**قواعد اللجنة (من الكود والمصادر — والتعارض موثّق أدناه):**

- عتبة اللجنة في الخطة **85** (`docs/TAGGING_PLAN_NUR.md` §3: «عتبة اللجنة **٨٥**»)،
  لكن `assign_route` في `src/v2_verify.py:392` يرشّح فعلياً عند `score >= 75` مع يقين `explicit/strong` وبلا أعلام.
  ⚠️ **تعارض مصادر**: اتبع سلوك الكود (75) واذكر العتبتين في التقرير والعرض.
- `M_RAY` يُحال للمتخصص دائماً (`src/v2_verify.py:380-381`)، وكذلك
  `FORCE_SPECIALIST_METHODS = {M_ISRAILIYYAT, M_NUZUL, M_QIRAAT}` (`src/v2_verify.py:49`).
- اليقين `weak` أو `insufficient` ← `specialist` دائماً (`src/v2_verify.py:382-383`).
- عند الخلاف بين الوكيلين: **الحكم الأشد (`specialist`)** حتى يحسمه نص حرفي أو المتخصص.

## 3. التشغيل خطوة بخطوة (المختصر — الكامل في `references/runbook.md`)

1. متغيرات **جلسة الطرفية فقط** (PowerShell على Windows)، لا ملف ولا git ولا شات:
   `$env:PYTHONIOENCODING="utf-8"`، `$env:LLM_API_KEY="ollama"`، `$env:LLM_BASE_URL="http://localhost:11434/v1"`.
2. `ollama pull <model>` ثم `ollama list` — وسجّل **الوسم الفعلي** في `committee.json` وفي العرض (`docs/TAGGING_PLAN_NUR.md` §3).
3. ابدأ بـ `--dry-run` (بلا شبكة) قبل أي استدعاء.
4. **عيّنة 24:35 أولاً على التفاسير الأربعة** (معرّفات النوافذ الحقيقية من `data/nur/<tafsir>/windows/`):
   الطبري `24_35_p01`…`24_35_p04`، ابن كثير `24_35_p01`…`24_35_p03`،
   البغوي `24_35`، السعدي `24_35` — ثم **توقّف** للمراجعة (القسم 5 من الخطة).
5. بعد قبول العيّنة: التشغيل الجماعي لكل تفسير عبر `src/run_surah.py` ثم المدقّق من العائلة الثانية ثم الفاحص الحتمي.
6. **commit واحد لكل تفسير** يذكر اسم النموذج الفعلي وتاريخ التشغيل؛ العمل على فرعك ثم PR — **ممنوع الدفع إلى `main`** (`AGENTS.md` القاعدة 8).

## 4. قواعد صلبة (انسخها كما هي)

- ممنوع لمس `data/**/{raw,layers,spans,windows}` — لا كتابة ولا تعديل ولا إعادة تقطيع.
- ممنوع إعادة كتابة نص التفسير أو تطبيعه أو الاقتباس منه خارج `rationale_ar` (≤ 25 كلمة، بلا اقتباس > 4 كلمات).
- ممنوع إنشاء أي اعتماد أو وسمه — **المتخصص البشري فقط** يعتمد.
- ممنوع وضع مفاتيح API في ملف أو git أو شات — متغير بيئة الجلسة فقط.
- الرد اليدوي الملصوق من أي محادثة = **«غير مضمون المدخل» (`manual_unverified`) ولا يُرشَّح أبداً** (`src/grounding_contract.py:44`).
- الأرقام **«أعداد توجيه وليست دقة»** — بلا نسب مئوية وبلا ادعاء دقة (`docs/COMMITTEE_PLAN.md` §و-4).
- الصياغة: **«لم ندرّب»** (بنينا طريقة تعمل مع أي نموذج)، **«وكيلان»** لا ثلاثة، ولا كلمة «الأول» لوصف النماذج.
- كلمة «محلي» فقط لتشغيل Ollama على الجهاز (`LLM_BASE_URL` نحو `http://localhost:11434/v1`) — غير ذلك يُكتب **«مستضاف»** مع اسم المضيف.

## 5. رايات حمراء — توقّف وصعّد

- **نتيجة كلها اتفاق = علامة شك لا نجاح** — أوقف التشغيل وراجع (`docs/TAGGING_PLAN_NUR.md` §5).
- `PACKET_HASH_MISMATCH` (تغيّرت الحزمة) — يمنع الترشيح؛ أعد التشغيل على الحزمة الحالية.
- تكرر `RUN_FAILURE` (شبكة/مهلة/خطأ نموذج) — سجّله إخفاقاً، لا اقتراحاً.
- اسم نموذج في التقرير لم يظهر في `ollama list` فعلاً — لا تذكره.
- أي خلاف بين الوكيلين أو شاهد بعيد/فارغ/من حاشية فقط ← `specialist`، لا تخمين.
